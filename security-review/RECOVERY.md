# Production backup and recovery (review only)
Do not execute production changes until explicitly approved. No backup has yet been taken.
1. Verify current Render branch, deployed commit, environment variable names (never export values to GitHub), and actual backend DB role using a trusted backend session.
2. From a trusted workstation with PostgreSQL 17 client, set PGHOST, PGPORT, PGUSER and PGDATABASE from the Supabase session pooler settings; use a protected password prompt or .pgpass. Do not put credentials in command history. Require TLS (PGSSLMODE=require).
3. Run pg_dump --format=custom --schema=public --file=kaamsetu-presecurity.dump . Save encrypted offline; do not upload to GitHub. Run pg_restore --list kaamsetu-presecurity.dump and record SHA-256. Capture grants, role memberships, RLS flags and default privileges separately. This is an application-schema backup, not a full Supabase project backup; separately inventory storage and external media.
4. Restore into an isolated PostgreSQL 17 database with required roles and extensions, using pg_restore --exit-on-error --dbname=kaamsetu_restore kaamsetu-presecurity.dump . Never restore over production for a rehearsal. Compare row counts and test dummy accounts. Keep backup confidential.
5. Verify no direct Data API clients depend on anon/authenticated grants; inspect Data API settings and default privileges. Verify live backend role, run CI and review dependency audit. Confirm rollback script matches current ACLs.
6. After explicit approval only: apply database-up.sql in a transaction; verify all 25 tables and all revoked privileges, and test website and Android with approved test accounts. Deploy backend patch separately after tests pass. Record prior deployed commit.
7. If database compatibility fails, prefer narrow corrective grants to the required trusted role. Emergency database-down.sql restores insecure grants and must be temporary. If backend regression occurs, redeploy prior known-good commit. Do not restore data unless data loss is confirmed and separately approved; coordinate writes to avoid losing newer records.
